为什么要做这个网站

去年（2025）二三月份为了换工作而疯狂投简历时，偶遇一家提供 CMS 建站服务的公司。久违地遇到 "CMS" 这个词，脑中的记忆被瞬间激活。我想起了多年前使用 Wordpress、在如今看来已经有些"幼稚"的建站经历。

入门编程这么多年，为了学习技术看了不少的教程、文章等，也看到不少好看的、或者有着新奇动画/粒子效果的、让人眼前一亮的网站。于是总有几次会突发奇想，想着自己也要做（或者说——抄）一个这样的网站。但往往想法是美好的，实际做起来才发现一点都不简单。

好看的设计见多了，便总想着这里抄一点，那里也要参考参考，结果各种纠结内耗，基本上开了个头便无疾而终。没有系统地学习过设计的小白自然是无法做到一个完整统一的设计。

也曾经想过，不如就用那些博客平台一类的建站算了。但也是注册个账号后便没了下文。

现在想来，其实我的主要目的似乎并不是要建站后用这个它做些什么，而是单纯地在体验建站的这个过程。

指着月亮的手指并不是月亮，但我总是会不自觉地看向手指。

于是痛定思痛，我发现问题并不出在代码层面，而是卡在内容规划和视觉设计上——我很容易在真正开始做一件事情前就想太多。比如要预先定义多少标签？如何划分分类目录？样式风格怎么统一？是否需要多语言支持？而我又特别怕麻烦——毕竟编程的目的不就是为了减少手动劳作嘛。纠结到最后往往还没动工就丧失了动力。

完成比完美更重要。于是最终决定，这次以内容为主，首先要让自己能写下去，其他不重要的一律靠后。

当然，在最终确定技术栈、开始写这篇文章前，还是度过了不短的一段纠结期。

（而现在这已经是这篇文章的第三个版本了。）

核心动力

抛开建站兴趣这个因素不谈，最根本的驱动力在于我确实需要一个内容平台。

我喜欢学习，也认为自己喜欢学习。但可能是学生时代的影响，我始终没法放下"学了就要记笔记，否则就等于没学"这个念头。但我又不喜欢用一些笔记平台或软件，也不喜欢东一个 .txt 西一个 .doc，整理是个大麻烦。于是就懒得记笔记，也就往往难以开始学习。而学过的知识不做一个记录实在是容易引发焦虑，而这又会导致难以开展新的学习。恶性循环了属于是。

技术选型

首要原则是一切为写作服务。先让自己能写下去，其他不重要的一律靠后。这不仅意味着需要顺手的编辑器，更要求一个能够最大限度消除包括懒惰在内的一切写作阻力的解决方案。

回顾之前用 Next.js + Markdown 文档，以及 Next.js + 用作 CMS 的 Github issues 的经历后，我意识到了一个强大的 CMS 的重要性。而说到 CMS，虽说不是经验丰富，也曾经浅尝辄止过 Wordpress（PHP）和 Wagtail（Python）。

但作为一个半路出家的前端程序员，对 MDX 的支持成了目前最主要的考量。再结合轻量化和成本，最终选了 TinaCMS。有瑕疵，但勉强够用。

接下来是前端部分。

对 React 的熟悉让我本能地想选择以 React 为基础的一些解决方案。但出于对 React 近年发展方向的一些不安，加上当时接触到了 Astro，虽然难以割舍 React 生态和 UI 库，但考虑到本网站以内容优先，于是初版最终选择了 Astro。

但 Astro 的高自由度意味着需要自己动手的部分也多，为了避免手写各种组件和 CSS，最终还是换回了 Next.js。也就是第二版和目前这个版本。这并不代表我有多喜欢这个框架（React 目前的问题基本上出自 Next.js 背后的公司），纯粹是 React 生态里做 SSG 没有更好的选择了。

第三版？

为什么要做第三版？

第三版和第二版在实现上其实差别不大。第二版其实也正常上线并持续了一段时间。最终让我放弃的原因还是——麻烦。

当时正是生成式 AI 大火的时候，我在编码中也大量用到了 AI 的辅助。初版和第二版就是在 AI 的帮助下建立的。但代码越写越乱，视觉设计选择困难，复杂功能停滞不前，再加上一些现实因素，于是第二版就默默沉寂了小半年。

而2026年1月的现在，AI 的代码能力更加强大，再加上第二版的经验，这次争取把之前踩过的坑都避开。

多语言

网站虽然加入了多语言，但主要可能还是以中文写作为主，其他语言基本靠AI翻译（赞美 AI）。翻译质量无法保证，有空我可能会手动校对。只能说……凑合看吧。
